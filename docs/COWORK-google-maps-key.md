# CoWork task — Google Maps key for the Android build

**Goal:** make the map render in the Masjid Locator Android app. Everything
else is already done; without this one key the map is a blank grey rectangle
while the rest of the app works normally.

**Supervised by:** Sheheryaar. Two steps need his Google account and his Expo
dashboard, so don't do those alone — ask him to drive, or to confirm each one.

---

## Already done — do not repeat

- Repo linked to the EAS project (`@shezzi/masjid-locator`, committed in `app.json`)
- `EXPO_PUBLIC_SUPABASE_URL` and `EXPO_PUBLIC_SUPABASE_ANON_KEY` set on EAS for
  the `preview` and `production` environments
- Android keystore generated by EAS
- A first `preview` APK build started — **it will have a grey map**, because the
  key below did not exist yet

## What is missing

`GOOGLE_MAPS_ANDROID_API_KEY`. [app.config.js](../app.config.js) injects it into
the Android manifest at build time. It is deliberately **not** in the repo — the
repo must never contain this key.

---

## Step 1 — Create the API key (needs Sheheryaar's Google account)

1. Go to https://console.cloud.google.com
2. Create a project (or pick an existing one) — e.g. "Masjid Locator"
3. **APIs & Services → Library** → search **Maps SDK for Android** → **Enable**
   - Google requires a billing account to be attached. The Maps SDK for Android
     has a generous free tier; a trial app will not approach it. Sheheryaar
     should confirm he's happy to attach billing before you continue.
4. **APIs & Services → Credentials → Create credentials → API key**
5. Copy the key. **Do not paste it into the repo, a commit, or a chat message.**

## Step 2 — Get the signing fingerprint (needs the Expo dashboard)

The key must be locked to this app, and Google identifies the app by its package
name plus the SHA-1 of the certificate it was signed with. EAS signs with its
own keystore, which is **not** the local debug one.

1. Go to https://expo.dev/accounts/shezzi/projects/masjid-locator/credentials
2. Open the Android application identifier `com.sheheryaarbaber.masjidlocator`
3. Under the keystore, copy the **SHA-1 Certificate Fingerprint**
   (looks like `AB:CD:12:...`, 20 pairs)

Alternatively, run `npx eas-cli credentials` locally and pick
Android → keystore → it prints the same fingerprint. That command is
interactive, so it needs a real terminal.

## Step 3 — Restrict the key

Back in Google Cloud Console, on the API key:

- **Application restrictions → Android apps → Add**
  - Package name: `com.sheheryaarbaber.masjidlocator`
  - SHA-1: the fingerprint from step 2
- **API restrictions → Restrict key →** select **Maps SDK for Android** only
- Save

Restricting matters: an unrestricted Maps key found in an APK can be extracted
and used by anyone, billed to this account.

## Step 4 — Give the key to EAS

From the repo root:

```bash
npx eas-cli env:set --name GOOGLE_MAPS_ANDROID_API_KEY --value <the-key> --visibility secret --scope project --environment preview --environment production --type string
```

`secret` is right here (unlike the Supabase anon key, which is plaintext because
it ships publicly by design). Secret values can be used by builds but never read
back out of the dashboard.

Verify it registered — this prints names, and secrets show as hidden:

```bash
npx eas-cli env:list --environment preview
```

## Step 5 — Rebuild

```bash
npx eas-cli build --profile preview --platform android
```

~10–20 minutes on the free tier. When it finishes, install the new APK over the
old one and open a place — the map should now render tiles.

---

## If the map is still grey

Work through these in order; the first two cover almost every case.

1. **Fingerprint mismatch.** Most likely cause. Re-check the SHA-1 in step 2
   matches what's in Google Cloud exactly, and that the package name is
   `com.sheheryaarbaber.masjidlocator` with no trailing space.
2. **Maps SDK for Android not enabled**, or enabled on a *different* Google
   Cloud project from the one the key belongs to.
3. **Billing not attached** to that project.
4. **Built before the variable was set.** The key is baked in at build time —
   setting it after a build does nothing until you rebuild.
5. Check the device log while opening the map:
   `adb logcat | findstr /i "Google Maps Android API"` — it states the reason
   plainly, usually an authorization failure naming the fingerprint it saw.

## Do not

- Commit the key, or put it in `.env.example`, or paste it into a chat/ticket
- Set it as a GitHub Actions secret — it is not used by CI
- Touch `SUPABASE_SERVICE_ROLE_KEY`; it must never exist outside GitHub Actions
- Leave the key unrestricted "just to test" — restrict it from the start
